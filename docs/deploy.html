Deployment

askbot has no daemon, no queue and no build step — deployment is a web server, a PHP interpreter and a database. That makes the checklist short, and worth doing properly.

Apache vhost

Point the document root at src/ and allow .htaccess overrides so the shipped rewrite rule works:

/etc/apache2/sites-available/askbot.conf
<VirtualHost *:80>
    ServerName ask.example.com
    DocumentRoot /var/www/askbot/src

    <Directory /var/www/askbot/src>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
shell
sudo a2enmod rewrite
sudo a2ensite askbot
sudo systemctl reload apache2
Only src/ belongs under the document root. Keeping the repository one level above it means .git/ and everything else outside src/ is never reachable from the web.

Subdirectory installs

Running the board under https://example.com/askbot/ instead of its own hostname works — two things need to know about the prefix:

The rewrite base

Uncomment and set RewriteBase /askbot/ in src/.htaccess.

The base URL

Make sure $_ENV["baseurl"] in app/config.standard.php includes the subdirectory, e.g. https://example.com/askbot/.

TLS

Sessions and passwords travel over this connection — terminate TLS in front of the board. On a plain Apache host, certbot does the whole thing:

shell
sudo apt install certbot python3-certbot-apache
sudo certbot --apache -d ask.example.com

Behind a reverse proxy (Traefik, nginx, a Cloudflare tunnel) the same rule applies: the proxy owns the certificate, Apache serves the board on the internal leg.

MySQL

Give the board its own database and its own user, with rights on that database only:

mysql
CREATE DATABASE askbot;
CREATE USER "askbot"@"localhost" IDENTIFIED BY "a-long-random-password";
GRANT ALL PRIVILEGES ON askbot.* TO "askbot"@"localhost";
FLUSH PRIVILEGES;

The connection string ends up in app/config.standard.php, written by the installer: mysql://askbot:password@localhost/askbot/.

Local development

Any local Apache + PHP + MySQL bundle works — XAMPP on Windows is the setup the .htaccess comments were written against. Clone into htdocs, set RewriteBase if you are in a subdirectory, create a database and let the installer run. The default config the installer writes for local use looks like:

app/config.standard.php (local)
<?php

$_ENV["config"]["db"][0]["conn"] = "mysql://root:@localhost/askbot/";

$_ENV["baseurl"] = "http://127.0.0.1:8082/askbot/";

Backups

Two things hold state: the database and the config file. Everything else is reproducible from git.

shell
# the content
mysqldump --single-transaction askbot > askbot-$(date +%F).sql

# the config (and any custom skins you added)
tar czf askbot-files-$(date +%F).tgz \
    /var/www/askbot/src/app/config.standard.php \
    /var/www/askbot/src/skins

Restoring is the same trip backwards: restore the dump, put the config back, git clone the code.

Updates

shell
cd /var/www/askbot
mysqldump --single-transaction askbot > pre-update.sql
git pull

The config file is untracked and survives the pull. Backup first, always — it turns a bad update from an incident into an inconvenience.
