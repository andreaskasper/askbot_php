Documentation

Everything here describes what is in the repository today. askbot is deliberately small: a front controller, a directory of page controllers, a MySQL schema and a skin. If you can read PHP, you can read all of it in an afternoon.

Requirements

askbot runs on the classic LAMP stack:

ComponentNotes
ApacheWith mod_rewrite enabled — the shipped .htaccess routes every request that is not a real file onto index.php. Other web servers work if you translate that one rule.
PHPA standard PHP installation with the MySQL and gettext extensions. Compatibility with current PHP releases is a focus of the next version — see the roadmap.
MySQL / MariaDBOne schema, created by the installer from app/code/install.mysql.sql.

Installation

There is no configuration to write by hand. The rule is simple: as long as app/config.standard.php does not exist, every request is routed into the installer (routing.install.php). Once the installer has written that file, the same requests reach the board.

Clone the repository

shell
cd /var/www
git clone --depth 1 https://github.com/andreaskasper/askbot_php.git askbot

Point your document root (or an alias) at askbot/src/. For a subdirectory install, uncomment and set RewriteBase in src/.htaccess.

Prepare the database

mysql
CREATE DATABASE askbot;
CREATE USER "askbot"@"localhost" IDENTIFIED BY "secret";
GRANT ALL PRIVILEGES ON askbot.* TO "askbot"@"localhost";

Run the installer

Open the site in a browser. The installer checks that it can write into app/, asks for the database connection and base URL, creates the schema and writes app/config.standard.php. After that the board is live.

The installer needs write access to src/app/ once — that is where it writes the config. After installation you can and should take that write access away again; see Security.

Configuration

The whole runtime configuration is one small PHP file, written by the installer and read on every request:

src/app/config.standard.php
<?php

$_ENV["config"]["db"][0]["conn"] = "mysql://askbot:secret@localhost/askbot/";

$_ENV["baseurl"] = "https://ask.example.com/";
KeyMeaning
config.db.0.connThe primary database connection as a URL: mysql://user:password@host/database/. The array index leaves room for more than one connection.
baseurlThe public URL of the board, used to build links. Include the subdirectory if you installed in one.

Site-level settings beyond these — the Akismet key, for example — live in the database and are managed as SiteConfig values rather than in the file.

Directory layout

PathWhat lives there
src/index.phpThe front controller. Defines the allowed entry point, loads the config (or the installer) and hands over to the router.
src/.htaccessThe rewrite rule: anything that is not a real file or directory becomes a request to index.php.
src/app/code/classes/The classes: database access, users, questions, karma, badges, antispam, social sharing and friends.
src/app/code/controller/One file per page, grouped by area — frontend/ask.php, frontend/question.php, frontend/login.php, frontend/settings.php and so on.
src/app/code/helper/Small shared helpers.
src/app/code/includes/Bootstrap includes: standard.php, routing.php, routing.install.php, lastseen.php.
src/app/code/crons/cron.php for scheduled maintenance — see Cron.
src/app/code/install.mysql.sqlThe database schema the installer applies.
src/app/plugins/Drop-in plugins; mainme404 ships as an example.
src/skins/Presentation. default is the skin to copy when you build your own.
src/locales/Gettext translations: de_DE, en_US and the frontend.pot template.
src/vendor/Bundled third-party code.

Features

What the board does, in the order a visitor meets it:

FeatureHow it behaves
AskingQuestions are asked with tags. Anonymous visitors pass a captcha (ask_antispam.php) before the question is accepted.
AnsweringLogged-in users answer directly; guests answer behind the captcha. If a SiteConfig Akismet key is set, anonymous answers are also checked against Akismet and flagged as spam rather than published when they fail.
CommentsOn questions and answers, for logged-in users, with a minimum length — comments are for substance, not for “+1”.
EditingQuestions and answers can be edited after the fact (question_edit.php, answer_edit.php).
TagsEvery tag has an info page that can itself be edited (tags_info.php, tags_infoedit.php) — a small wiki inside the board.
KarmaActions run through a rule engine (Karma::RuleAction) — creating an answer, for example, earns the author karma.
BadgesMilestones award badges: the first answer, the first comment, and more.
AccountsRegistration, login, logout, a profile with editable settings and a rights page (userprofile_rights.php).
SharingQuestions carry share links for social networks (?share=twitter, ?share=facebook).
Last seenlastseen.php tracks activity, so the board knows what is new for whom.

Skins

Presentation is separated from code. A skin is a directory under src/skins/; the shipped default skin is the reference implementation and the natural starting point:

shell
cp -r src/skins/default src/skins/myskin
# edit src/skins/myskin/ until it looks like yours

Skin files are real files on disk, so the rewrite rule leaves them alone and Apache serves them directly — no PHP in the hot path for assets.

Localisation

askbot speaks gettext. Translations live in src/locales/, with de_DE and en_US included and frontend.pot as the template for new languages. Adding a language is a translation job:

Copy the template

Start from frontend.pot and translate the strings into a new .po file for your locale.

Compile and drop it in

Compile to .mo with msgfmt and place it under src/locales/<your_LOCALE>/ following the existing layout.

Regenerate when strings change

locales/create_pot.do rebuilds the .pot template from the source code.

Plugins

Plugins are directories under src/app/plugins/. The repository ships mainme404 as a working example — read it to see the shape: a plugin brings its own code and is picked up from its directory. The plugin surface is intentionally thin today; growing it is a candidate for the next version.

Cron

Recurring maintenance runs through src/app/code/crons/cron.php. Schedule it with the system crontab:

crontab
*/15 * * * * php /var/www/askbot/src/app/code/crons/cron.php

Updating

An installation is a git checkout, so updating is a pull:

shell
cd /var/www/askbot
git pull

Your app/config.standard.php is not tracked by git and survives the pull. Take a database backup first — the deployment guide shows how.
