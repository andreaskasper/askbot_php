askbot is a lightweight, self-hosted Q/A board written in plain PHP on MySQL. Questions get a permanent home, answers get votes, karma and badges keep people coming back — and all of it lives on your own server. No framework, no build step: clone, click through the installer, start asking.

The problem

Good answers keep getting lost

Someone asks in chat, someone answers in a thread, and three weeks later the same question is asked again — because chat scrolls away, mail stays in one inbox, and a wiki nobody asks questions in stays empty. A Q/A board is the shape knowledge actually arrives in: as a question.

Without Answers scattered everywhere

  • Chat answers scroll out of sight the moment the next topic starts
  • The same question gets answered five times by five different people
  • Knowledge lives in inboxes and leaves with the person who owns them
  • There is no signal for which of three conflicting answers is the right one
  • Hosted Q/A platforms own your content, their ads and their export button

With askbot Answers with an address

  • Every question gets a permanent URL you can link to the next time it comes up
  • Votes and accepted answers make the best answer visible at a glance
  • Karma and badges reward the people who actually answer
  • Tags with editable info pages keep topics organised
  • Everything sits in a MySQL database on your own server — yours to query, back up and keep

How it works

A front controller and a database

Apache rewrites every request that is not a real file onto index.php, which routes it to a controller. Skins render the page, gettext translates it, MySQL remembers it. That is the whole machine — which is why it runs on any ordinary LAMP host.

Questions, answers, comments

The full Q/A shape: ask with tags, answer, comment on both, edit later. Guests can answer too — behind a captcha, so the board stays open without drowning in spam.

Karma and badges

A rule-driven karma system and badges like “first answer” give contributors something to earn. The signal doubles as moderation: reputation is visible.

Tags with their own pages

Tags organise the board, and each tag has an editable info page — a place for the definition, the conventions, the “read this before asking”.

Spam handled twice

A captcha challenge for anonymous posts, and optional Akismet checking when you configure an API key. Suspicious answers are flagged, not silently published.

Skins and locales

Presentation lives in skins/ — copy the default skin and make it yours. Language lives in locales/ as gettext files, with de_DE and en_US included.

A database you own

One MySQL schema, installed by the setup wizard from a plain install.mysql.sql. Your content answers to mysqldump, not to an export button.

In practice

One rewrite rule, one config file

The routing is four lines of Apache config that ship with the code, and the configuration the installer writes for you is two lines of PHP. There is very little machinery to understand — deliberately.

src/.htaccess
RewriteEngine On

# Installing in a subdirectory? Set the base:
#RewriteBase /askbot/

RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule (.+) index.php [L]
app/config.standard.php — written by the installer
<?php

$_ENV["config"]["db"][0]["conn"]
    = "mysql://askbot:secret@localhost/askbot/";

$_ENV["baseurl"]
    = "https://ask.example.com/";
Everything else is convention. Controllers live in app/code/controller/, one file per page: ask.php, question.php, login.php, settings.php. Adding a page means adding a file — the router finds it by name.

Quick start

Running in three steps

Get the code

Clone into your web root. You need Apache with mod_rewrite, PHP and a MySQL server — the classic LAMP stack.

shell
cd /var/www
git clone --depth 1 https://github.com/andreaskasper/askbot_php.git askbot
# document root points at askbot/src/

Create a database

An empty schema and a user with rights on it. The installer creates the tables itself.

mysql
CREATE DATABASE askbot;
CREATE USER "askbot"@"localhost" IDENTIFIED BY "secret";
GRANT ALL PRIVILEGES ON askbot.* TO "askbot"@"localhost";

Open it in the browser

As long as app/config.standard.php does not exist, every request starts the installer. It checks that it can write its config, creates the schema and writes the two-line configuration for you. When it is done, the board is live and the first question is yours to ask.

Put it behind TLS. Logins and sessions travel over this connection. The deployment guide has a full Apache vhost, a Let's Encrypt setup and the hardening checklist for the database user and file permissions.
