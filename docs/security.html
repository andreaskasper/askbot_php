Security

askbot is self-hosted, which means the security of an installation is shared work: the code brings its protections, and the operator brings the perimeter. This page covers both halves honestly.

Reporting a vulnerability

Found something? Please report it privately first: use GitHub's private vulnerability reporting on the repository. For anything that does not put installations at risk — hardening suggestions, questions about this page — a public issue is fine.

You will get an honest answer about whether it is real, how bad it is, and when a fix lands.

An honest posture

This codebase has roots in the SourceForge era of PHP. It is small enough to audit in an afternoon — and it deserves that audit before you put it in front of the open internet with real users. A security-review pass over input handling and authentication is one of the working themes of the next version.

Recommendation: for an internal knowledge base behind a VPN or SSO proxy, askbot is a fine fit today. For a fully public, anonymous-write deployment, review the code first and keep backups tight — as you would with any small open-source web app.

Operator checklist

Terminate TLS in front

Sessions and passwords travel over this connection. Certbot on the vhost or a reverse proxy — either way, no plain HTTP in production. Setup.

Scope the database user

One user, rights on the askbot schema only, long random password. The connection string sits in app/config.standard.php — a scoped user limits what a leak of that file is worth.

Take write access back after installing

The installer needs to write into src/app/ exactly once, to create the config. After that, the web server user does not need write access to the code — remove it.

Keep the repository out of the web root

Serve src/, not the repository. That keeps .git/ and everything else unreachable. Vhost example.

Back up like you mean it

A nightly mysqldump plus the config file is the whole disaster-recovery story. Commands.

Keep the platform current

Most real-world compromises of small PHP apps come through outdated PHP, Apache or MySQL. Patch the platform; git pull the board.

Built-in protections

ProtectionWhat it does
Captcha for guestsAnonymous questions and answers must pass a captcha challenge before they are accepted.
Akismet (optional)With an API key configured in SiteConfig, anonymous answers are checked against Akismet. Failing content is flagged as spam instead of being published.
Comment thresholdComments require a logged-in account and a minimum length — drive-by spam has nowhere to land.
Single entry pointAll requests flow through index.php; the code guards its includes with an entry-point constant so internal files cannot be executed directly.
Author IP loggingAnswers record the author's IP, which makes cleanup and blocking after a spam wave practical.
Scope note: askbot stores no payment data and needs no third-party accounts to run. The data worth protecting is your users' emails, password hashes and content — the checklist above is built around exactly that.
